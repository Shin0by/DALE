## ADR-002: coordinates and raster
Positions use original JPG pixels:
image_x = (wall_x - origin_x - background_offset_x) * image_width / scene_width, likewise Y.
Reject nonidentity background scale/rotation and EXIF rotation. Padding needs alignment evidence. No visible height/origin controls. Internal placement/coordinate primitives are not a compatibility adapter or Foundry importer.

Masks are immutable snapshots. Geometry edits never move artwork or regenerate masks. Preview does not limit export resolution.

## ADR-003: graph editing
Snapping prefers vertices, then interiors; exclude dragged-node incident edges. Alt-drag projects onto the original approached segment vector; toggle mid-drag. Reconciliation epsilon is 1e-7 source pixels.

Cursor Auto-close and Close all contours extend existing free ends forward along vectors. Required travel distances must fit configured screen tolerance; facing collinear tips meet halfway when the full gap fits. T/shared contacts are noded. No standalone bridge or sideways movement. White edges/dashed extensions preview a frozen plan; Cancel/Yes precedes mutation; one undo snapshot. No-op clicks explain.

Eraser hover/deletion share hit tests; swept circles prevent missed edges. Ordinary vertex deletion reconnects two neighbors; branches remove incident edges. No source writes.

## ADR-004: selected cells and transforms
Expose minimum polygonized cells separately from mask union. Toggle smallest covering cell; neighboring cells remain independent. Fill continuous closed QPainterPath rings translucent cyan.

Move regions freezes a geometry plan. Related-line mode uses indexed transitive reachability within snap tolerance. Without related lines detach branches and retain shared walls for stationary neighbors. Move regions drag translates and Ctrl-wheel scales 5%. A separate Rotate regions mode consumes plain wheel for 0.1 degree clockwise/counterclockwise rotation per notch without view zoom. Both modes share related-line settings/right-click configuration and persist their active mode. Remove the Alt-wheel rotation handler. Common bounding-box center remains fixed through scaling/rotation, moves with translation. Undo/redo stores geometry only; raster/masks stay fixed. Yes/No/Cancel dialog, optional remembered choice; right-click reopens; loading never prompts.

Required isolation, pending NEXT-009: freeze membership before the transform. Do not snap, repair, extend lines toward stationary neighbors or grow the group during the gesture. The owner reported unwanted extensions while moving/rotating; the research update records the defect without claiming an implementation fix.

## ADR-005: ancestry and project format

## ADR-006: separate bounded exports
All-regions exports current connected components; explicit selection exports cells. The left Artwork offset (-4096..4096 source pixels, stored as contour_offset) expands/contracts retained JPG pixels relative to lines. It is the only margin control: no automatic 3px guard or global transparent-padding setting.

For export, substitute the current offset union for outside-mask boundaries at their existing history positions. Replay brushes and inside masks in order, then constrain each item to its own current offset contour. Project/preview mask snapshots remain immutable; geometry still never moves source artwork. This makes changing the live artwork offset effective in export even after a previous outside mask.

Render alpha only at 2x resolution and reduce with Pillow BICUBIC. Two-source-pixel filter halos on all stripe/crop sides avoid seams and discover complete filter support; they are an internal sampling extent, not an exported fixed border. Scan source-aligned alpha stripes before RGB decoding; getbbox includes every nonzero byte, even 1/255. Crop to this actual alpha box, clipped to JPG. The same renderer encodes PNG and supplies Information dimensions. A 32-entry cache keyed by size/immutable raster operations/contour avoids repeated sidebar scans. No full native alpha bitmap is retained. Native source RGB is unchanged, including under partial alpha; zero-alpha RGB stays compacted.

Fully transparent items are skipped, an entirely transparent set is rejected, and outside selections report no bounds. Stage a complete new directory and rename on success. Placement manifest schema 2 records artwork_offset_px, alpha_antialiasing, bounds_mode and each item's source-coordinate content_bounds. Removed guard/padding metadata has no fallback. Current project UI serialization omits the retired export-padding preference; no migration or alias is added.

placement.json is a DALE coordinate manifest, not native Foundry import. Foundry 13/14/elevation primitives retain placement intent; actual elevation/visibility is set in Foundry.

## ADR-010: editable circular contours

Circles are regular closed polygons in existing GeometryEdit snapshots, not a new archive primitive. Press fixes the center; drag changes radius; release commits one undo step. Preview and commit use the same vertices. No ordinary snapping is applied while drawing. Exact contact vertices split existing edges and inherit parents through LineageBuilder; unaffected IDs remain stable. Existing point/line tools, region selection, transforms, masks and PNG export can operate on the result without adapters.

Use source grid cell size (numeric Dungeon Alchemist export or Foundry grid.size), converted to image pixels. Missing/invalid grids use an explicit 100-source-pixel editing fallback; it is not inferred scene metadata. For diameter d in cells: 4 vertices for d<=0.5, 6 for d<=1, 8 for d<=2; otherwise min(4096, 8+2*ceil((d-2)/2.5)). Zoom does not change density. This owner-selected sparse approximation intentionally makes small circles square/hexagonal. Do not add subpixel-error tessellation or regenerate the polygon after ordinary point edits. Ctrl+wheel adjusts the active radius in screen pixels, Escape/Clear selection cancels.

Foundry Regions support native circle and polygon shapes, while walls use straight segments. Future serialization should preserve the edited polygon as Region polygon/individual walls; emitting a native circle requires a future explicit semantic primitive and round-trip rules. Existing original JSON remains unchanged. See foundry-export-feasibility.md for sources and limitations.

## Resource and evidence boundaries

Exact PNG bounds for sidebar information are coordinated by bounds_preview.py. Crops totaling at most 262,144 candidate pixels are immediate; larger calculations use one Qt worker with immutable Session/polygon snapshots and cancellation between alpha stripes. Keep only the newest pending request and apply results only for the current geometry/selection/raster/offset key. A bounded 16-result cache avoids repeated scans. Pending information says calculating exact bounds; do not show stale dimensions or substitute approximate boxes. Export still computes identical exact nonzero alpha bounds.

Canvas raster rendering is keyed only by scene image size and raster mask/stroke snapshots. A contour-only edit changes geometry without rebuilding the same RGBA preview/QPixmap. Raster edits and undo/redo invalidate this key. Stop/cancel the bounds worker before window shutdown; the worker never decodes source RGB or accesses temporary project files.

Read-only profiling of three owner daytime scenes (13500x16200) found synchronous sidebar alpha scans dominated the reported pause: ground-scene refreshes 698-725 ms, geometry edits about 4 ms. With background bounds and raster reuse, profiled UI refreshes were 20-38 ms for that scene, 4-5 ms for the other two. This measures the tested update path, not a universal latency guarantee. Synthetic Qt tests verify live event-loop progress during a held worker and rejection of obsolete offset requests.
JPG max 16384 per side; warn above 8192. Reduced preview, decoded source plus 128-row export stripes, memory preflight/cancellable worker. Source decoding is not interruptible; no bitmap undo history.

Real sample evidence: docs/sample-formats.md; six owner JPG/JSON pairs and the independent Foundry 13.351 scene probe are present locally. Semantic evidence and future export design: docs/foundry-scene-format.md and docs/foundry-export-feasibility.md. Current export-margin regression checks use synthetic fixtures. No semantic segmentation, live Foundry connection/native scene generation/verified live floor assembly.
Archive ownership checks resolve both source and workspace paths before comparing containment; Windows short-name/junction aliases must not cause active assets to be deleted. Retain active extracted JPG/JSON until their session is replaced or closed.

Per-level working walls use wall_assignments.py plus an assignment-only wall_assignments_ui.py page. Session history includes immutable WallAssignmentEdit snapshots, resolving derived edges through explicit ancestry. Cache instance materialization by operation identities/level IDs and canvas segments by session/history/library/current-level identity. Every edge has a default independent instance on every level; no coordinate-based semantic matching. Brushes alter only properties with one undo per swept stroke. Native Foundry generation remains separate. See wall-assignments.md.

DALE becomes one local project for assembling multiple levels from repeatedly imported images and scene JSON documents. The Level editor prepares source material; explicit Copy to level creates independently editable floors and walls on the level selected in Main. The project retains both prepared materials and composed level contents. Original assets remain immutable. The required final deliverable now includes a full Foundry scene package under ADR-012; selected-region PNG extraction remains available.

This replaces the current single-pair replacement workflow, automatic existence of every edge on every level, the Templates page arrangement and the absence of project-coordinate controls. Existing contour tools, raster masks, exact PNG cropping, numeric-setting scope, source provenance and bilingual help remain required.

### Project model and coordinates

| Entity | Planned responsibility |

| Project | Stable ID, explicit bounds, material catalog, ordered levels, shared wall presets, project command history and saved UI state. |

Use project pixels as the common placement space. Native image pixels retain their resolution. Preserve the existing explicit scene-to-image conversion for associated JSON, then apply material placement to obtain project coordinates. Keep source-image, source-scene and project coordinates distinct in models and serialization. JSON-only layers initially use their declared scene coordinates in project pixels; associating an image is an explicit alignment action, never a filename-based scale guess.

Freeze each prepared layer's source-to-local conversion at import. Associating an already edited JSON-only layer with an image creates a new associated layer from the original JSON using the explicitly previewed conversion; retain the edited standalone layer. Never reinterpret existing vertex coordinates, mask history or already copied objects under a new scale. Treat material movement as placement of the whole prepared material (geometry and raster together); existing region-transform tools still move geometry only. This distinction avoids applying a project offset twice or moving pixels during a contour-only operation.

The first successfully imported image initializes bounds exactly once to (0, 0, width, height). Earlier JSON-only imports do not initialize bounds. Later imports, reordering and removal of the original image do not reset or enlarge them. New images initially use project position (0, 0), with native dimensions and no stretching; the material catalog exposes editable X/Y placement for alignment.

Initialization belongs to the first image-import command: undoing that command in normal history order restores the preceding uninitialized bounds; redo restores its exact initialized bounds. An ordinary later Delete material command preserves existing bounds. Opening a saved project restores serialized bounds and initialization state without inspecting which image currently comes first. Failed image imports never initialize them.

Settings contains a Project bounds block with editable Start X, Start Y, End X, End Y and read-only Width/Height. Require finite coordinates within the existing supported coordinate range, End X > Start X and End Y > Start Y; negative starts are valid. Apply all four values atomically in one undoable command. Bounds change the work area and fit target while preserving object coordinates, source pixels and masks. Objects outside the bounds are retained; changing bounds does not destructively crop or rescale anything. Existing source-image limits continue to apply per image, not to the overall project span. Before the first image, show bounds as uninitialized and keep Apply disabled.

### Wall double-click configuration

In Walls, double-click a current-level segment to open the existing standard wall-preset editor. If it has a preset, open that exact linked definition, prefilled with its current values/name/RGB/icon. Saving that existing preset updates all its explicit references, including other levels; show its shared scope and reference count in the dialog. Also provide Save as new preset: allocate a fresh definition ID from the edited values and bind only the clicked segment. Other selected segments and checked-level painting scopes do not enlarge this double-click command.

For an unassigned segment, prefill the same editor from its effective source/default settings and offer saving a named new preset, assigned to that segment in the same atomic project command. Allow correction of every supported preset field before saving. Never create a preset merely by opening/cancelling the dialog. Cancel/Escape changes neither definitions, assignments nor geometry; undo restores the whole saved definition/binding operation. Presets have no heights/coordinates; retain the level-derived wall interval separately. If several coincident wall instances are hit, choose the instance before opening its settings.

Double-click dispatch must not first commit a reset/paint stroke or move/delete/split a wall. Preserve normal drag-brush responsiveness while arbitrating single-click versus double-click with Qt's actual system interval. Add actual-event regression coverage for both property brushes and overlapping segments; an abstract dialog-unit test alone cannot prove this interaction safe.

Owner clarification: adding contours to an already populated level is strictly additive. Append new wall instances to that level's existing graph; retain every previous contour/wall/floor, its ID, coordinates, ancestry and preset assignment. Never initialize or replace the level from the latest selection or import. Coincident newly copied lines do not authorize deleting, resetting or replacing existing ones. Undo of a copy removes only that command's newly added objects; redo restores them alongside the earlier contents. Apply the same preservation rule to floor additions. Copying never changes the target's height range.

Owner exception: a complete duplicate contour/wall on the same target level may be skipped only when its exact project-coordinate geometry and all properties match. Compare oriented endpoints/contour edges, complete effective wall properties (restrictions, door/animation/threshold values, RGB/icon and derived level heights) and the preset binding, including default-versus-explicit binding. Two distinct preset IDs with equal present values are not interchangeable: later preset edits must remain independent. Endpoint reversal is equivalent only when it preserves every directional/side-dependent meaning; otherwise it is a different instance. No tolerance, rounding, partial overlap, geometric union or property reset qualifies as duplicate suppression. Different properties at identical coordinates create an additional instance; another level remains an independent destination. Skipping preserves the existing instance's identity, ancestry and assignments; retain the new source in the material catalog without fabricating lineage links. Report added/skipped counts. A contour-only operation containing only exact duplicates adds no history entry. Region copying still produces its floor when wall boundaries are skipped; matching contours do not imply matching raster pixels.

The owning collection is an instance-ID multigraph: different walls at identical coordinates may coexist. Geometry tools and region transforms continue to leave raster snapshots in place. Each floor's elevation equals its level's finite bottom. Every wall obtains bottom/top dynamically from its owning level; presets contain no height copies. Changing level bounds updates wall height interpretation and floor elevation without touching X/Y or raster bytes.

Latest owner-resolved policy: every DALE level must have a finite signed hundredth-foot bottom in the existing supported height range, even if it has no floors or contains only walls. ### Logic rules easy to miss

- Identity and equality: use stable object IDs and explicit source correspondence. Compare duplicate walls exactly after resolving their actual bindings/settings. Never treat coincident geometry as one object or silently merge different presets. Batch duplicates among new candidates follow the same rule. A duplicate-only contour copy creates no undo step; a region copy can still add its floor.
- Source semantics and direction: legacy-style Dungeon Alchemist sense enums need deliberate verified conversion to native restrictions. Owner selected source-setting preservation; store unassigned settings explicitly and let an assigned preset override them. New manual lines and deliberate Reset use ordinary settings. Double-click opens the prefilled common editor, with existing-shared versus new-single-segment save scope clearly separated. Splitting a door must not create several unintended interactive doors; reject an unresolved semantic split or keep a defined single door span with tested ancestry. Endpoint reversal must preserve one-way restrictions and animated hinges.
- Copy versus replacement: a copied floor is independent and its stored image bytes remain immutable. Moving a placed floor moves its linked named footprint, not walls. Source contour transforms move geometry only; source material placement moves the whole material. Owner-approved floor recuts use an isolated existing editor route and a distinct atomic Apply to floor command that updates derived asset references, never an implicit Copy overwrite.
- Holes: keep logical floor footprints distinct from retained artwork and alpha. A raster eraser's transparent patch does not silently invent walls or a gameplay hole. A portal polygon does not automatically cut a PNG. Stored floor Region holes remain explicit ordered geometry; the PNG may include artwork beyond the footprint through Artwork offset.
- Coordinates: import source canvas/padding to material pixels once, then material placement to project pixels, then a single project-to-target transform. Grid origin follows the same mapping. Tile width/height are pixel dimensions; Tile.elevation, Region bounds and Wall Height flags are vertical scene units. Neither DPI nor preview zoom changes native pixels.
- Height roles: walls follow the whole level interval; floors follow its finite bottom; portals use an explicitly chosen activation policy and destination bottom. Default0..+infinity is intentional and is not auto-shortened by adding another level. Source null/finite-swapped flags remain byte-exact even when authored/generated settings differ.
- Bounds/background: changing Start while keeping the same dimensions can require a different background result. Bounds are nondestructive in the editor; full export reports outside placed contents instead of dropping them. First-image undo differs from deleting its material row. The designated background survives catalog deletion and remains independent of source eraser masks.
- Selection/context: preparation source, current displayed level and preset application scope are different. Text Ctrl+A selects text; global Select all selects the active subject. Covered images need list access. Overlapping walls need instance choice. Switching contexts cancels a preview; it never redirects an already staged copy.
- Lifetimes/async: hash and validate the frozen imported bytes. Keep every source/derived asset referenced by live objects, ancestry, undo, redo or workers. Project activation/history generation invalidates pending copy publication even when reopened IDs match. Save sees committed state only. Queue large exact scans in one bounded cancellable worker, with no ready-result repaint during active gestures.
- Portal links: source confirmation and destination are independent of reciprocal settings. Names/colors are display properties, not references. Target deletion and level deletion clean incoming links atomically. Same-XY cross-level connections need visible arrow geometry. Native Region visibility controls are not a promise that colored portals appear to all players; keep the default native layer visibility unless explicitly changed.
- Export completeness: full export ignores selection and exports committed authored content only. Floor name/PNG stems are unique/stable; portal names are independent and need no PNG. Resolve every media dependency and Foundry Data prefix. No Windows/temporary paths, duplicated project translation, stale scene UUIDs or re-JPEG recompression. Tests cover filename normalization/Unicode/case collisions and empty or transparent outputs.
- World boundaries: preserve raw input lights/tokens/Actors/macros/journals/flags in the source catalog. Owner requires imported lights on the initial default level; convert/add them explicitly without automatically changing Scene darkness or doubling exact duplicates. Keep source labels and enabled/delete controls for overlapping alternatives. Other world-owned entities remain excluded unless deliberately supported; do not execute scripts or copy dangling references.
- Delivery: document updates do not prove source correctness; unit tests do not prove Foundry runtime behavior; source-world portal success does not prove new-scene ID remapping. Keep these evidence types labeled. The existing portable build stays available while incomplete source work is repaired.

### Visibility contract

The desired automatic player view uses the token's base elevation in scene units. A floor at elevation F is eligible when F<=token elevation; floors above the token are hidden. Thus a token standing exactly on a floor or slightly above it still sees its artwork. Eligible floors compose by elevation and persisted same-level floor order; opaque pixels of a nearer floor cover lower images, while holes and partially transparent pixels reveal lower eligible content. This is visibility through image alpha, not an x-ray view through an opaque floor. Walls, lighting, sight, fog, ownership and line of sight still constrain what a player can see.

Do not select floors by level.top or whichever overlapping level interval contains the token: default level0..+infinity must not suppress upper floor identities. Do not use physical token height as the floor switch point or invent an arbitrary positive tolerance; token-base elevation already handles the requested slightly-above case. At equal elevations use explicit persisted draw order, never hash/native array coincidence. GM editing view remains independently useful; no global scene-hidden toggle may stand in for per-player token-height behavior. Verify multiple controlled tokens at different elevations and different players, rather than assuming one shared global current level.

The owner requested this if supported. Foundry13 + Wall Height is still the chosen candidate, and an additional Levels dependency has not been accepted. Native Tile elevation/occlusion fields and a valid JSON are evidence of serialized options, not proof of the whole visibility predicate. First test a minimal two-floor scene with an opaque area, a stair hole and token elevations just below/exactly at/above each floor. Record an exact runtime limitation if the chosen profile cannot implement this behavior, then return that specific dependency/profile decision to the owner. Do not silently substitute manual switching or claim a floor preset alone implements missing runtime capability.
