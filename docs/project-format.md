# DALE project schema7

Optional UI figure_scale_step_percent is a strict integer1..100, default5, shared by Scale contours and Move contours scaling. It follows the existing per-dataset/project numeric values and global override rules. Internal Scale figures is a valid editing mode. No new archive member or schema version is required.

ADR-028 extends native wall editing beyond ADR-021 coordinate repair. Original JSON remains an exact immutable member; export writes a separate copy with every byte outside the root walls array preserved.

Current scope: single-scene contour/PNG editing with full source-wall edits and native-preserving export (ADR-028). Production currently supports schema7 only; reject older/unknown schemas without migrations. The owner requires a rolling current/previous format window for future changes, independent of app versions: introducing schema8 retains7, introducing9 retains8. Do not reintroduce schema1..6 readers. The [storage research](project-storage-research.md) is a proposal, not an implemented schema8. No authored levels/presets/portals.

## Members and validation

Required ZIP members: manifest.json (64KiB), history.json (no byte-size cap). Manifest source_kind is image or json. Image projects require sources/map.image (1GiB), containing exact static JPEG/PNG/WebP/BMP/TIFF bytes; detect format from bytes. JSON-only projects omit the image member and require sources/scene.json; explicit native scene width/height define the coordinate canvas. JSON members are declared in json_documents: source uses sources/scene.json, other IDs use sources/json/<id>.json. IDs match [A-Za-z0-9_-]{1,64}; no per-JSON or combined JSON byte-size cap, catalog0..100 entries. No templates, assignments, authored levels or portal entities.

Manifest: format=dale-project, schema_version=7, app_version, source_kind, nullable image_name/scene_name, sha256 for every payload, and json_documents entries {id,name,kind,member}, kind original/updated. An empty catalog is valid for image-only work. Reject extra/duplicate/encrypted/oversized/traversal members and checksum failures before accepting a project. Save to a sibling temporary ZIP, verify its structure, then atomically publish; never replace a source or source hard link. Preserve all source bytes, freezing original JSON at import including whitespace, BOM and number spellings.

## Applied geometry and raster state

ADR-125 supersedes persisted undo/redo. The schema7 member history.json retains its structural keys: origin, gap_tolerance, contour_offset, operations, redo and UI. New saves store current geometry and exact applied raster recipes in protected operations; redo is empty and undo_floor protects the complete state. Selection actions and obsolete geometry are omitted. All datasets reopen with empty undo/redo. Existing schema7 archives are scanned before deserialization, skipping old coordinate snapshots and redo while preserving current provenance and DA metadata. Saving does not clear live undo/redo. Operation kinds: closure, geometry, source_repair, mask, stroke. Mask stores area, mode and an explicit nullable boundary (the immutable unoffset snapshot); validate polygon type/validity/bounds. Preserve it in applied archive state and live undo/redo. Current Artwork offset is applied to stored boundaries in preview and export, avoiding different results after a project round-trip. New UI masks freeze only explicitly selected polygons; changing selection does not retarget them. Select raster regions is a validated current schema7 mode. Marquee previews/baselines are transient and never serialized.

Every edge has persistent ID, parents and exact sources (JSON SHA256, original /walls/index, optional native ID). Splits/clones create children, merges union ancestry, detached manual lines are editor roots. Moves/extensions retain identity. Preserve deleted ancestors and validate all parents/source references against the embedded source or exact declared catalog JSON used by copied ancestry. Never infer ancestry from old coordinates. Geometry transforms leave raster/masks in place.

source_repair is a GeometryEdit snapshot with an explicit repair type in applied and redo history. It retains the original edge prefix/count/order/source lineage, followed only by explicitly created walls, with no closure paths. Each source_repair snapshot requires additions: an ordered array {native_id,bottom,top} matching its new-wall tail. Validate unique16-character alphanumeric native IDs against original IDs, strict nullable finite height bounds and editor lineage. New walls retain identity/settings through moves/repair and applied/redo snapshots; reject missing/invalid metadata. Inferred bands are derived references, not persisted wall copies or authored floors. A shared source wall has one coordinate state across all bands. Ambiguous heights/conflicting dependent groups remain unchanged and reported. Automatic signed vector repair (ADR-023) can extend or shorten free ends within tolerance, retaining native IDs and all existing covered-layer contacts; the same source_repair snapshot format stores both without a schema change. Undo/redo restores accepted changes together.

UI stores safe_json_repair (boolean), source_layer (validated choice key), Contours/Regions/Raster mode, language, viewport, contour visibility, selected minimum cells, related-line choice and ten independent numeric tool values: geometry line/point erasers, raster erase/restore, local/global close distance, snapping and Artwork offset. No Foundry version/elevation or semantic wall settings. Language, input/output directories, recent projects and global numeric settings merge in portable preferences; extraction paths are never remembered. Saving with global overrides retains the project's own numeric values. Current projects reopen without external files.

## Original Scene JSON repair export

Export JSON uses the active source Scene whenever present, regardless of height filtering. Reuse exact original wall text and coordinate-token patches where possible; otherwise replace only the root walls array. Retain opaque wall settings via explicit property ownership, preserve unchanged IDs/order, allocate stable unique child/copy IDs and ordinary defaults for new roots. All non-wall bytes, internal paths/names and invisible zero-length source records remain intact. Output is an atomic new copy; original member/input bytes stay unchanged.

JSON-only input and native-height image/JSON pairs enable height filtering automatically. The checkbox is Edit contours by height layers; it only selects the editing scope and never disables erasers, insertion/deletion or native-preserving export. Inferred band/exact-range choices refer to one canonical source wall rather than creating copies. General geometry, closure paths and imported ownership remain editable after topology changes.


## Current contour catalog and alignment UI

Optional current_contours_id references one declared updated JSON containing current DALE contours in image pixels (width/height/grid and c per working/path edge). Working line IDs are not generated Foundry IDs. Original Scene properties stay in the exact original member. Validate the cache against applied history and omit it from explicit session.json_documents; replace it on save. Current schema7 archives without a cache derive it on catalog read. Redo/raster changes never become applied contour changes. Catalog reads validate source/history/ancestry, opening only image headers.

Optional UI right_angle_alignment and contour_alignment booleans default false; right_angle_tolerance_deg is integer1..90 degrees default5; contour_alignment_distance_px remains integer1..9999 screen pixels default14. Optional right_angle_neighbours is strict bool default true, belongs to project/dataset UI, and enables fixed-neighbour angle candidates. Missing angular settings use the declared default; never convert or reinterpret the retired pixel field. Values follow existing numeric global/project precedence; toggles belong to the project. Optional UI/derivative fields do not change schema7 operation serialization.

Optional right_angle_own_priority is strict bool default true. It belongs to each dataset's UI and prioritizes own-corner angle constraints; false prioritizes adjacent angles and acquired X/Y guides instead. Compatible constraints still combine. Numeric global overrides do not replace this flag. No new archive member or schema version.

Optional section_region_selections contains exactly regions and pixels keys. Each value is null or an array of at most100000 integer cell indices in0..99999; booleans/fractions are invalid. Normalize duplicates/order like export_regions. The existing export_regions field describes the active section; detached_region_selection retains the Regions shape even if another section is active. Runtime section switching preserves these independent selections and hides inactive highlights. Missing optional metadata retains only the existing selection in its applicable section. Stale topology invalidates inactive cell indices before capture. This UI-only metadata does not change schema7 or archive members.

Optional manifest custom_colors is one project-wide16-slot Custom Colors palette. It is an array of exactly16 #aarrggbb strings, accepting hex case and normalizing to lowercase. Reject invalid type/count/hex entries before extraction; absent metadata gives16 white #ffffffff slots. Keep slot order and alpha. It is separate from per-dataset UI and global numeric settings. Save/Save As and dataset append retain the appropriate project palette. Palette edits affect dirty state but add no geometry history. Existing archive schema7 and member layout remain unchanged.

Section toggle independence (ADR-039): snap_enabled, right_angle_alignment and contour_alignment store Vertices controls even when another section is active. Optional figure_point_alignment, figure_guide_alignment, region_point_alignment and region_guide_alignment are strictly boolean; point defaults true and guide defaults false. Persist every section independently in root/dataset UI snapshots and apply the active section on opening or switching. Numeric tolerance values remain shared; these flags are not global numeric overrides.


## Optional catalog sets and editing views (ADR-026)

A JSON catalog entry may include image_member and image_name. image_member is either sources/map.image (image-root projects only), or sources/images/<64-lowercase-SHA256>.image; the latter filename digest must equal manifest.sha256. image_name is required with the member,1..256 characters; forbid a name without an association. Shared content reuses one ZIP payload. Each additional image has the same1GiB/static-format/dimension/EXIF checks as the root source, and is checksum verified on extraction. Original input names persist independently of temporary paths.

Optional catalog_views=true declares catalog-views.json (hashed, no byte-size cap). Its version1 structure contains base_name (nullable1..251-character set alias) and up to255 additional views. Each view has json and image selection IDs (nullable), optional name, and a normal history object with origin/gap/offset/operations/redo/UI. JSON IDs reference the original source or explicit static catalog; image IDs are source-image or a stable hash of member/name. Reject unknown/duplicate selections and invalid history/provenance. Raw pair catalogs start at the creation pair. Managed UI restoration may select the last visited dataset without replacing the physical source root. Source-only creation stays source-only even after more assets are added.

Per-view UI numeric values retain project values beneath global overrides. Archive save captures the active draft, serializes the base session as the existing root history, and stores other drafts in catalog-views.json. A common clipboard copies no pixels; cross-source copied ancestry is validated against exact JSON retained in the destination catalog. Every referenced SourceWall still requires the actual original SHA256/index/native ID. Applied provenance is checked; archived redo is discarded before operation decoding.

Appending to a selected existing project streams all existing payloads unchanged (manifest alone changes), adds one fresh explicit JSON ID and any missing image bytes, checks the old target SHA256 before atomic publish, and never activates the target. Existing static exact copies may skip. A generated current_contours_id cache is replaceable and therefore never suppresses a new permanent revision. The catalog retains the100-document limit without a combined JSON byte-size cap. Snapshot export names come from source JSON, otherwise image stem plus.json; an explicit set alias takes precedence. Safe Foundry JSON repair remains separate.


Optional catalog_images is an independent array of up to100{name,member} entries. Names1..256; members must be sources/images/<SHA256>.image with matching declared hash, no duplicate name/member pairs. It permits image-only sets without JSON documents. Members are whitelisted/size-checked and hash-verified on extraction/save. A content member may be shared by this registry and JSON associations.

Catalog view version1 also records default:[json-id-or-null,image-id-or-null], validated to exist in the views (the root pair is included logically). This pair-catalog field does not alter the physical root; managed dataset reopening follows the datasets.json default and local navigation preference described below. Explicit replacement of the first set rebases its assets and root session, remaps other drafts needing old root inputs, and removes the replaced draft plus unreferenced input files. New root source_name/image_name replace the first pair's previous names. Exact external originals remain untouched; shared/ancestry-required inputs stay declared. Image-only replacement freezes corrected geometry in history when dimensions differ, preserving original pixel coordinates and lineage. Replacing a JSON starts new contour history against that exact new source. Independent Add never rebases the first set.


## Named dataset registry (ADR-027)

Current schema7 additionally accepts datasets:true with one hashed datasets.json (no byte-size cap); it is mutually exclusive with catalog_views. Its version1 object declares default as a valid existing selected set ID and sets with1..256 records. The first record remains the physical root independently of the reopening selection. Each record has an immutable set-<32 lowercase hex> ID, unique file-safe name, explicit two-integer size, nullable declared JSON ID/image member, nullable original input names and independent filename labels, plus applied state/UI in the existing validated structure. References must resolve to whitelisted/hash-checked assets. The first record supplies the physical root source/history; all remaining sources are declared exact catalog payloads. Identical image bytes may share immutable storage, while set state and labels remain independent. Original input names may reach256 characters; newly assigned set/file stems are limited to240.

source_kind=empty has no physical root image/original JSON, requires explicit empty_size, and permits a truly empty portable project with multiple independent empty sets. No shared-size fallback is used. Current schema7 archives with the existing optional catalogs remain current inputs; older/unknown schemas are still rejected. Sources required by applied lineage are retained in the archive; live undo/redo keeps its own references. Unused replaced inputs are pruned on save. Physical export filenames follow the set name without rewriting values inside native JSON.

A source_repair addition may additionally declare source_ref:{json_sha256,wall_index,foundry_id} and properties (both required together). These are imported JSON contours, not default manual walls. The immutable serialized properties exclude c/_id/id and must match the exact referenced embedded source record. Validate source references, property payloads and unique valid native IDs. Preserve original source prefix/IDs/history; append imported records with current coordinates and original properties. wall_intervals reads imported properties directly so invalid heights remain ambiguous rather than receiving guessed bounds. Ordinary manual additions keep their existing three-field encoding/defaults. Both types support edits, undo/redo and strict native coordinate/addition export.

The external alchemist-cache.sqlite3 stores metadata, versioned ten-band model-coordinate polygon WKB profiles and small preview PNGs. It is excluded from delivery/projects and contains no original model/texture files or map placement data. Existing projects reopen using their generated geometry without this cache.

Large geometry snapshots with more than10000 line records omit the optional derived vertices diagnostics. Exact walls, lineage, ancestry, connection groups and wall properties remain serialized. Vertex diagnostics are recomputed from those authoritative records on read, as for smaller snapshots. This avoids redundant identity data without reducing geometry or changing schema7.


Optional DA slab data in schema7 stores ten base64-encoded WKB polygons per shared block ID and each object's six-coefficient image transform plus automatic band index and strict signed-height inversion flag. Validate catalog identity, bounded bytes/coordinates, polygon validity and affine invertibility. Optional geometry alchemist_slices has four strict integers-1..10, participates in undo/redo and survives history checkpointing. Missing values mean automatic selection; missing profiles leave existing edited contours intact and require a geometry import before slab switching. No3D meshes or textures enter the project.

Empty selected slabs retain an optional alchemist_empty_frames tuple of object ID, invertible affine placement and explicit ancestry anchor. It survives save/history checkpointing so returning from an empty slab preserves position without resurrecting intentionally deleted objects.

ADR-120 adds optional strict alchemist.alpha_projection (default false). It selects the alpha-aware external-outline policy for that dataset's cached slabs and affine regeneration baseline. New geometry imports set true; absent/false retains the existing non-alpha outline policy. No model, texture, neural network or external dependency is stored in the project; the ten compact2D profiles remain sufficient offline. External cache format5 replaces pre-alpha profiles and uses versioned preview keys. Detailed imported objects use an explicit object-level property ancestor, with derived edges retaining independent IDs and connection groups; this shares wall settings without changing schema7 or archive limits.

ADR-121 / FR-184 adds optional GeometryEdit.alchemist_object_slices, an array of [object ID, [lower, upper, enabled]] entries. Lower is an integer-1..10, upper0..10, enabled is a strict bool; an enabled range requires0 <= lower <= upper. The latest supplied map survives checkpoints/undo/redo and overrides the category fallback for the specified object only. Entries imply the contact-preserving external-boundary policy for that regenerated object. Optional alchemist.separate_projection_parts defaults false and is true for new geometry imports. Retain the previous policy when fitting existing placements; never silently rewrite reopened contours.

The64MiB history.json/datasets.json/catalog-views.json ceiling and size-based undo tail reduction are removed. No hard byte ceiling applies to these state members. The existing100-action checkpoint policy and exact content/hash/source validation remain. Full selected contours can use optional ui.figure_components entries [anchor ID, member count, SHA256 of sorted IDs encoded as compact JSON]. ui.figure_lines retains partial contours. Loading validates each reference against the current stored-vertex/connection-group component, expands exact IDs for editing, and rejects duplicates or mismatches. This representation also applies to inactive dataset views.

Optional GeometryEdit.alchemist_complexity stores unique [object ID, maximum vertices] entries. Values are strict integers4..2147483647. Latest targets survive checkpointing, undo/redo and offline reopening; regenerated raw slices receive the target after range union. Merged simplified edges preserve explicit arc ancestry for affine placement and native property resolution.

Optional GeometryEdit.alchemist_detail_frames stores unique [object ID, six-value raw affine matrix, three anchors] entries for outward-simplified contours. Each anchor contains [line ID, endpoint0/1, x, y]. IDs, finite bounded numbers, nondegenerate matrices and noncollinear anchor triples are validated. Latest frames survive history checkpoints and archive reopening. They distinguish outward boundary expansion from later instance transforms during raw slice regeneration; missing live anchors fall back to the existing explicit-ancestry placement path. Frames never enter native Scene JSON.


Optional GeometryEdit.alchemist_transforms stores unique [object ID, relative scale, relative rotation degrees] entries. Scale is finite and positive within1e-9..1e9; rotation is normalized to[-180,180). Values describe explicit DALE transforms relative to initial import, and survive applied-state checkpoints and live undo. Missing values default to1/0 for new explicit edits. Global per-type defaults live only in the portable SQLite item_settings table, never in the .dale archive; opening a project cannot override its applied geometry with those defaults.

Geometry snapshots may contain optional `alchemist_thinning: [level, scope_ids, hidden_ids]`. Level is a strict integer0..10; IDs are unique strings, hidden IDs belong to the scope, and level0 has no hidden IDs. The latest applied value survives checkpoint compaction and save/reopen in schema7. It hides complete DA objects in display/export scopes without removing stored coordinates. Undo/redo remains live-session-only. Old archives without this field show all otherwise enabled objects.
