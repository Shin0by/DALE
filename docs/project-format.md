# DALE project schema7

ADR-028 extends native wall editing beyond ADR-021 coordinate repair. Original JSON remains an exact immutable member; export writes a separate copy with every byte outside the root walls array preserved.

Current scope: single-scene contour/PNG editing with full source-wall edits and native-preserving export (ADR-028). Only schema7 is supported; reject older/unknown schemas without migrations. No authored levels/presets/portals.

## Members and validation

Required ZIP members: manifest.json (64KiB), history.json (64MiB). Manifest source_kind is image or json. Image projects require sources/map.image (1GiB), containing exact static JPEG/PNG/WebP/BMP/TIFF bytes; detect format from bytes. JSON-only projects omit the image member and require sources/scene.json; explicit native scene width/height define the coordinate canvas. JSON members are declared in json_documents: source uses sources/scene.json, other IDs use sources/json/<id>.json. IDs match [A-Za-z0-9_-]{1,64}; each JSON <=32MiB, combined <=128MiB, catalog0..100 entries. No templates, assignments, authored levels or portal entities.

Manifest: format=dale-project, schema_version=7, app_version, source_kind, nullable image_name/scene_name, sha256 for every payload, and json_documents entries {id,name,kind,member}, kind original/updated. An empty catalog is valid for image-only work. Reject extra/duplicate/encrypted/oversized/traversal members and checksum failures before accepting a project. Save to a sibling temporary ZIP, verify its structure, then atomically publish; never replace a source or source hard link. Preserve all source bytes, freezing original JSON at import including whitespace, BOM and number spellings.

## Geometry and history

History contains origin, gap_tolerance, contour_offset, operations, redo and UI. Operation kinds: closure, geometry, source_repair, mask, stroke. Mask stores area, mode and an explicit nullable boundary (the immutable unoffset snapshot); validate polygon type/validity/bounds. Preserve it in applied and redo state. Current Artwork offset is applied to stored boundaries in preview and export, avoiding different results after a project round-trip. New UI masks freeze only explicitly selected polygons; changing selection does not retarget them. Select raster regions is a validated current schema7 mode. Marquee previews/baselines are transient and never serialized.

Every edge has persistent ID, parents and exact sources (JSON SHA256, original /walls/index, optional native ID). Splits/clones create children, merges union ancestry, detached manual lines are editor roots. Moves/extensions retain identity. Preserve deleted ancestors and validate all parents/source references against the embedded source or exact declared catalog JSON used by copied ancestry. Never infer ancestry from old coordinates. Geometry transforms leave raster/masks in place.

source_repair is a GeometryEdit snapshot with an explicit repair type in applied and redo history. It retains the original edge prefix/count/order/source lineage, followed only by explicitly created walls, with no closure paths. Each source_repair snapshot requires additions: an ordered array {native_id,bottom,top} matching its new-wall tail. Validate unique16-character alphanumeric native IDs against original IDs, strict nullable finite height bounds and editor lineage. New walls retain identity/settings through moves/repair and applied/redo snapshots; reject missing/invalid metadata. Inferred bands are derived references, not persisted wall copies or authored floors. A shared source wall has one coordinate state across all bands. Ambiguous heights/conflicting dependent groups remain unchanged and reported. Automatic signed vector repair (ADR-023) can extend or shorten free ends within tolerance, retaining native IDs and all existing covered-layer contacts; the same source_repair snapshot format stores both without a schema change. Undo/redo restores accepted changes together.

UI stores safe_json_repair (boolean), source_layer (validated choice key), Contours/Regions/Raster mode, language, viewport, contour visibility, selected minimum cells, related-line choice and ten independent numeric tool values: geometry line/point erasers, raster erase/restore, local/global close distance, snapping and Artwork offset. No Foundry version/elevation or semantic wall settings. Language, input/output directories, recent projects and global numeric settings merge in portable preferences; extraction paths are never remembered. Saving with global overrides retains the project's own numeric values. Current projects reopen without external files.

## Original Scene JSON repair export

Export JSON uses the active source Scene whenever present, regardless of height filtering. Reuse exact original wall text and coordinate-token patches where possible; otherwise replace only the root walls array. Retain opaque wall settings via explicit property ownership, preserve unchanged IDs/order, allocate stable unique child/copy IDs and ordinary defaults for new roots. All non-wall bytes, internal paths/names and invisible zero-length source records remain intact. Output is an atomic new copy; original member/input bytes stay unchanged.

JSON-only input and native-height image/JSON pairs enable height filtering automatically. The checkbox is Edit contours by height layers; it only selects the editing scope and never disables erasers, insertion/deletion or native-preserving export. Inferred band/exact-range choices refer to one canonical source wall rather than creating copies. General geometry, closure paths and imported ownership remain editable after topology changes.


## Current contour catalog and alignment UI

Optional current_contours_id references one declared updated JSON containing current DALE contours in image pixels (width/height/grid and c per working/path edge). Working line IDs are not generated Foundry IDs. Original Scene properties stay in the exact original member. Validate the cache against applied history and omit it from explicit session.json_documents; replace it on save. Current schema7 archives without a cache derive it on catalog read. Redo/raster changes never become applied contour changes. Catalog reads validate source/history/ancestry, opening only image headers.

Optional UI right_angle_alignment and contour_alignment booleans default false; right_angle_distance_px and contour_alignment_distance_px are integers1..9999 default14. Values follow existing numeric global/project precedence; toggles belong to the project. Optional UI/derivative fields do not change schema7 operation serialization.

Section toggle independence (ADR-039): snap_enabled, right_angle_alignment and contour_alignment store Vertices controls even when another section is active. Optional figure_point_alignment, figure_guide_alignment, region_point_alignment and region_guide_alignment are strictly boolean; point defaults true and guide defaults false. Persist every section independently in root/dataset UI snapshots and apply the active section on opening or switching. Numeric tolerance values remain shared; these flags are not global numeric overrides.


## Optional catalog sets and editing views (ADR-026)

A JSON catalog entry may include image_member and image_name. image_member is either sources/map.image (image-root projects only), or sources/images/<64-lowercase-SHA256>.image; the latter filename digest must equal manifest.sha256. image_name is required with the member,1..256 characters; forbid a name without an association. Shared content reuses one ZIP payload. Each additional image has the same1GiB/static-format/dimension/EXIF checks as the root source, and is checksum verified on extraction. Original input names persist independently of temporary paths.

Optional catalog_views=true declares catalog-views.json (64MiB, hashed). Its version1 structure contains base_name (nullable1..251-character set alias) and up to255 additional views. Each view has json and image selection IDs (nullable), optional name, and a normal history object with origin/gap/offset/operations/redo/UI. JSON IDs reference the original source or explicit static catalog; image IDs are source-image or a stable hash of member/name. Reject unknown/duplicate selections and invalid history/provenance. Always activate the creation pair on load; no saved active selection can replace the original root. Source-only creation stays source-only even after more assets are added.

Per-view UI numeric values retain project values beneath global overrides. Archive save captures the active draft, serializes the base session as the existing root history, and stores other drafts in catalog-views.json. A common clipboard copies no pixels; cross-source copied ancestry is validated against exact JSON retained in the destination catalog. Every referenced SourceWall still requires the actual original SHA256/index/native ID. Both applied and redo ancestors are checked.

Appending to a selected existing project streams all existing payloads unchanged (manifest alone changes), adds one fresh explicit JSON ID and any missing image bytes, checks the old target SHA256 before atomic publish, and never activates the target. Existing static exact copies may skip. A generated current_contours_id cache is replaceable and therefore never suppresses a new permanent revision. Limits remain100 declared JSON/128MiB combined. Snapshot export names come from source JSON, otherwise image stem plus.json; an explicit set alias takes precedence. Safe Foundry JSON repair remains separate.


Optional catalog_images is an independent array of up to100{name,member} entries. Names1..256; members must be sources/images/<SHA256>.image with matching declared hash, no duplicate name/member pairs. It permits image-only sets without JSON documents. Members are whitelisted/size-checked and hash-verified on extraction/save. A content member may be shared by this registry and JSON associations.

Catalog view version1 also records default:[json-id-or-null,image-id-or-null], validated to exist in the views (the root pair is included logically). Normal selection is not saved as the default. Explicit replacement of the first set rebases its assets and root session, remaps other drafts needing old root inputs, and removes the replaced draft plus unreferenced input files. New root source_name/image_name replace the first pair's previous names. Exact external originals remain untouched; shared/ancestry-required inputs stay declared. Image-only replacement freezes corrected geometry in history when dimensions differ, preserving original pixel coordinates and lineage. Replacing a JSON starts new contour history against that exact new source. Independent Add never rebases the first set.


## Named dataset registry (ADR-027)

Current schema7 additionally accepts datasets:true with one hashed datasets.json (64MiB limit); it is mutually exclusive with catalog_views. Its version1 object declares default equal to the first set ID and sets with1..256 records. Each record has an immutable set-<32 lowercase hex> ID, unique file-safe name, explicit two-integer size, nullable declared JSON ID/image member, nullable original input names and independent filename labels, plus full history/UI in the existing validated format. References must resolve to whitelisted/hash-checked assets. The first record supplies the physical root source/history; all remaining sources are declared exact catalog payloads. Identical image bytes may share immutable storage, while set state and labels remain independent. Original input names may reach256 characters; newly assigned set/file stems are limited to240.

source_kind=empty has no physical root image/original JSON, requires explicit empty_size, and permits a truly empty portable project with multiple independent empty sets. No shared-size fallback is used. Current schema7 archives with the existing optional catalogs remain current inputs; older/unknown schemas are still rejected. Sources required by applied/redo lineage are retained; unused replaced inputs are pruned on save. Physical export filenames follow the set name without rewriting values inside native JSON.

A source_repair addition may additionally declare source_ref:{json_sha256,wall_index,foundry_id} and properties (both required together). These are imported JSON contours, not default manual walls. The immutable serialized properties exclude c/_id/id and must match the exact referenced embedded source record. Validate source references, property payloads and unique valid native IDs. Preserve original source prefix/IDs/history; append imported records with current coordinates and original properties. wall_intervals reads imported properties directly so invalid heights remain ambiguous rather than receiving guessed bounds. Ordinary manual additions keep their existing three-field encoding/defaults. Both types support edits, undo/redo and strict native coordinate/addition export.

## Explicit wall ownership and independent region selection

A geometry snapshot may store wall_styles: a map from live/ancestral line IDs to nonempty lists of exact source references or inline properties. Each entry is {source:{json_sha256,wall_index,foundry_id}} or {properties:{...}} without c. Validate owner existence, bounds, finite JSON values and exact embedded source references. Source references resolve opaque original properties; editor roots use ordinary defaults independently of contact ancestry. Splits/copies inherit explicit styles and every applied/redo snapshot retains them. Current schema7 accepts this optional extension, without migrations or aliases.

Optional UI detached_region_selection has exactly lines, polygons and pivot. Lines name unique live IDs; polygons are bounded valid Polygon WKB hex; pivot is finite. Validate limits and live membership before restoring. This freezes whole independently transformed figures instead of reselecting clipped polygonized cells after overlap. Normal selection clears detached ownership. Point/guide alignment buttons use independent section switches (ADR-039) and shared numeric tolerances; no new tool-value schema.


Optional schema7 UI figure_lines is a list of at most100000 unique nonempty live line IDs (each at most256 characters); figure_pivot is null or a finite bounded point. The loader validates types/limits, and restoration retains only IDs live in the current geometry/height scope. tool_set accepts figures and mode accepts Select figures / Move figures / Rotate figures. Exact selected-line ownership is independent of detached_region_selection and ordinary polygonized cell indices. These fields also apply to per-dataset drafts. No geometry/asset schema, migration or legacy mode alias is introduced.


Current schema7 lineage records additionally accept nullable connection_group (nonempty string, at most128 characters). It names editing component membership for independent coincident vertices; source/parent identity remains unchanged. Every applied/redo snapshot stores current groups and node diagnostics may include connection_group. Moves retain groups, children inherit their parent's group, copies retain their source group. GeometryEdit connection_state is derived in memory, never separately serialized. Groups affect Figures/point editing only, not polygonization, raster masks, PNGs or native Scene JSON. The two remembered connection answers belong to portable preferences, not the archive numeric/global scope. Rotation series use one ordinary GeometryEdit; no new history operation/schema/migration.
